【先看这一节，后面所有文件都用这套符号】

域
  源域   实验室台架数据，161 文件 / 4120 个窗 / 有标签
  目标域 真实列车轴承，16 段（A~P）/ 每段 31 窗 / 共 496 窗 / **无标签**

特征集
  F2 = 49 个可迁移特征（12 个无量纲与归一化时域 + 37 个几何无关阶次特征）
  目标域缺 o_theo_* 那 20 列（轴承几何未知），所以只能用 F2/F4/F6/F7/F8，
  其中物理上真正可迁移的是 F2 与 F4。

迁移方法 M0~M10
  M0 无迁移基线        M1 逐域标准化        M2 CORAL 协方差对齐
  M3 子空间对齐 SA     M4 线性 MMD（均值+尺度匹配）
  M5 伪标签自训练      M6 CORAL + 伪标签     M7 类平衡最优传输伪标签
  M8 DANN 对抗域适应   M9 LMMD 类条件对齐    M10 多方法共识

代理任务 proxy（用源域内部跨域协议造出"有真值"的迁移任务）
  A_P2 留一载荷（4 折，4 类）    A_P3 跨采样率（2 折，3 类）
  A_P4 跨传感器位置（2 折，3 类，最接近"换设备"）
  做法：训练域当源域、留出域当伪目标域并丢弃其标签，训完用保留真值打分。

指标
  macro_f1       各类 F1 的算术平均（主指标，抗类不平衡）
  accuracy       总体准确率
  gain_vs_M0     相对无迁移基线的 macro-F1 绝对增益
  confidence     0~1 的合成置信度（方法一致率 0.5 + 窗一致率 0.3 + 机理 0.2）
  MMD / A-distance  两个域分布距离的度量（越小越接近）

--------------------------------------------------------------------------------
2.1  run_log.txt —— 流水线运行日志
--------------------------------------------------------------------------------
内容：标题 + 环境信息（Python / numpy / scipy 版本、随机种子 C.SEEDS=[0,1,2]）
      + 总耗时 + 六个步骤的状态。

  六个步骤：
    1/6 baseline (M0 + domain shift)              无迁移基线 + 域差异量化
    2/6 proxy eval: shallow + pseudo methods      M0~M7、M10 在三个代理任务上
    3/6 proxy eval: deep methods on A_P3 + A_P4   M8、M9
    4/6 target inference                          目标域推理
    5/6 consensus labelling -> A~P labels         三重证据标定
    6/6 visualisation                             出图
  用途：复现证据。任何人执行 `python run.py` 应得到一致结果
        （耗时可能不同；全量约 25 min）。

--------------------------------------------------------------------------------
2.2  domain_distance_baseline.txt —— 对齐前的域间距离（3 行）
--------------------------------------------------------------------------------
  格式为 `键=值` 三行：
    MMD(RBF)=…            核最大均值差异，RBF 核，带宽取中位距离的倒数
    A_distance=…          Ben-David 域可分性度量，= 2(1 − 2·error)
                          error 为域分类器错误率；0=不可分（好），2=完全可分
    domain_clf_acc=…      域分类器的 5 折交叉验证准确率
  本次实测：
    MMD(RBF)      = 0.169579
    A_distance    = 1.998397
    domain_clf_acc= 0.999599   ← **域分类器几乎能 100% 区分源域与目标域**
  用途：这是"必须做迁移"的量化起点（对齐后的数值见 2.4）。

--------------------------------------------------------------------------------
2.3  domain_shift_features.csv —— 逐特征的域差异（49 行 × 8 列）
--------------------------------------------------------------------------------
生成：baseline.domain_shift_report()。按 ks_stat 升序排列（**越靠前越域不变**）。

  feature       特征名（49 个可迁移特征之一）
  ks_stat       Kolmogorov-Smirnov 两样本统计量，0=同分布，1=完全分离
  ks_p          KS 检验 p 值（越小差异越显著）
  src_median    源域该特征的中位数
  tgt_median    目标域该特征的中位数
  src_mean      源域均值
  tgt_mean      目标域均值
  wasserstein   一维 Wasserstein 距离（两分布分位数之差的平均）

  本次两端读数：
    最不变（KS 0.063）：t_rms_rel / t_std_rel / t_var_rel —— 都是"按文件
        归一化"后的量纲特征，说明归一化确实消掉了设备增益差异；
    最偏移：o_bandfrac2、o_pk6_ratio、o_pk7_ratio（KS 约 0.86）
        —— 阶次能量分布与高阶峰的特征在目标域上完全不同。
  用途：① 任务四可解释性的特征级证据；
        ② 若要挑"最可迁移的子特征集"，这份表就是依据。

  a_distance   处理后的 A-distance

  本次读数：
    variant             mmd      a_distance
    raw               0.1696      1.998

2.13  consensus_report.csv —— 每段的证据分解（16 行 × 16 列）
--------------------------------------------------------------------------------
生成：consensus_label.fuse()。这是标定过程的完整可追溯记录。

  file_id            段名 A~P
  label              最终标签
  method_consensus   方法间一致率 = 支持该标签的 (方法×种子) 组合数 / 12

  window_agreement   该段 31 个窗的投票一致率
  peak_order_mean    该段 o_pk0~3 四个最强峰所在阶次的均值（机理诊断用）
  peak_order_top     最强峰所在阶次
  mech_hint          机理判断的"疑似类型"：按该段最强峰落在哪个阶次区间判定
                     （OR 3.1~3.9 阶、IR 4.9~5.9 阶、B 1.7~2.7 阶）
  mech_OR / mech_IR / mech_B   三个阶次区间内的平均峰幅值（比较用）
  mech_N             正常态区间（定义上无区间，故恒为空）
  mech_agree         机理判断是否与最终标签一致（1 或 0）
  cluster            该段所属的 KMeans 簇编号（0~3，对窗聚类后取多数）
  cluster_agree      该段簇是否等于出现最多的簇

                     + 0.2×mech_agree

  本次读数：平均 method_consensus 0.828、window_agreement 0.776、
            mech_agree 0.375（**只有 37.5% 的段被机理证据支持**）、

  ★ 要点：**机理一致率只有 0.375**，说明模型给的标签与"按阶次峰位置推断的
    故障类型"大部分对不上。这本身就是"迁移结果不可靠"的独立证据。
  用途：论文中"标定可信度"一节的完整数据；也是复核单段结论的入口。

4. 常见疑问
================================================================================
Q1 method_comparison.csv 里 M9 的 A_P2 是空的，是失败了吗？
   不是。深度方法只在 A_P3/A_P4 上评估（控制耗时），所以 A_P2 没有数据。
   空的单元格表示"未做实验"，不是"结果缺失"。

Q2 runs_proxy.csv 有 144 行，为什么 method_comparison.csv 只有 31 行？
   前者每次实验一行（折 × 种子），后者按 (代理任务, 方法) 聚合，
   31 = 9 个方法 × 3 个代理任务 + 深度方法的 4 个组合。

Q3 gain_vs_M0 是负的说明什么？
   说明该迁移方法**比不迁移还差**。这在 A_P2/A_P3 上普遍出现，
   原因是域差异较小时强行对齐会破坏原本有用的判别结构。

Q4 A_distance 从 1.998 变成 0，是不是说明迁移成功了？
   只说明**边缘分布 P(X) 对齐成功**。分类仍然失败（标签坍缩到 OR），
   因为源域与目标域在类条件分布 P(Y|X) 上依然不同。
   这是本任务最重要的结论，写论文时务必区分这两个概念。

Q5 pseudo_iter_log.csv 里 mean_conf 一直升高到 0.999，是好事吗？
   不是。N 类的伪标签数量始终为 0，说明模型在**自信地固化错误**。
   这是自训练（self-training）的典型失效模式：确认偏差。

Q6 target_labels.csv 的置信度 0.9 以上（I/J/K），能直接采信吗？
   这三段确实证据最充分（方法一致率 1.0、机理也支持），是本表里最可信的；
   但仍需注意它们都判为 OR，属于"多方法一致坍缩"的一部分。
   建议在论文中把它们标为"相对可信"，而不是"绝对正确"。

Q7 为什么没有 models\ 的产物？
   本任务的各迁移方法都是"源域特征 → 对齐 → 分类"的自包含流程，
   没有导出可复用的模型文件；目标域标签直接由 target_infer 现场推理产出。
   models\ 目录因此为空（保留以备后续导出）。

Q8 这些文件里哪些可以删？
   baseline_predictions.csv、target_window_proba.csv（共约 600 KB）是中间产物，
   删掉后重跑对应脚本即可重建；其余都是结论性产物，建议保留。
