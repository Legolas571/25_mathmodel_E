    lr 逻辑回归 / svm RBF 支持向量机 / rf 随机森林(300树) /
    hgb HistGradientBoosting(300轮) / mlp PyTorch三层MLP+Focal Loss /

0.4 指标定义
    accuracy      总体准确率（类别不平衡下会虚高，只作参考）
    macro_f1      各类 F1 的算术平均 ← **主指标**
    weighted_f1   按类样本数加权的 F1
    precision_X   查准率 = 判为该类且正确 / 判为该类
    recall_X      查全率 = 判为该类且正确 / 实际该类
    f1_X          该类 F1（查准与查全的调和平均）
    file_*        文件级版本：一个文件的所有窗多数投票后只算一个样本

0.5 窗口级 vs 文件级
    窗口级：1 样本 = 1 个 0.5 s 窗，源域 4120 个
    文件级：1 样本 = 1 个 .mat 文件，源域 161 个（31 个窗投票成 1 票）
    **文件级更接近工程实际**（一次诊断给整段记录一个结论）

2.1  splits_all.json —— 五套划分的完整文件清单（97 KB）
--------------------------------------------------------------------------------
生成脚本：make_splits.py

结构（三层嵌套）：
    {
      "P1": { "fold0": {"train": [file_id...], "test": [file_id...]},
              "fold1": {...}, ... "fold4": {...} },
      "P2": { "load0": {...}, "load1": {...}, "load2": {...}, "load3": {...} },
      "P3": { "12k_to_48k": {...}, "48k_to_12k": {...} },
      "P4": { "DE_to_FE": {...}, "FE_to_DE": {...} },
      "P5": { "fold0": ... "fold4": ... }
    }

  - 第一层键 = 协议名（P1~P5）
  - 第二层键 = 折名：
      P1/P5 → fold0~fold4         （5 折）
      P2    → load0~load3         （4 折，折名即被留出的载荷）
      P3    → 12k_to_48k / 48k_to_12k（2 折，折名即训练→测试方向）
      P4    → DE_to_FE / FE_to_DE （2 折）
  - 第三层 = train（训练文件清单）与 test（测试文件清单），
    元素是 file_id 字符串，例如 "12kHz_DE_data/B/0007/B007_0"

  已内置的三条硬校验（make_splits.py 会断言，不通过直接报错终止）：
    ① train ∩ test = ∅（同一文件绝不跨两侧）
    ② 所有 file_id 都属于 161 个源域文件
    ③ train 与 test 都非空

  本次规模：P1 每折 train 128~130 / test 31~33；
            P2 每折 train 120~121 / test 40~41；
            P3 105↔52（两个方向互为训练测试）；
            P4 60↔45；P5 train 43~47 / test 9~13。
  另外：P1 与任务一的 outputs/splits.json **完全一致**（同算法同种子 42），
        已在校验中确认。

2.3 ~ 2.5  runs_stage1.csv / runs_stage2.csv / runs_cnn1d.csv
--------------------------------------------------------------------------------
三个文件**列结构完全相同**（31 列，由 train_eval.RESULT_COLS 定义），
区别只是跑了哪些 (协议, 特征集, 模型, 种子)：

    runs_stage1.csv  1080 行   P1~P5 × F1/F2/F3/F6/F7 × lr/svm/rf/hgb × 种子 0,1,2
    runs_stage2.csv    44 行   P1/P2/P3 × F2/F3 × mlp/vote × 种子 0
    runs_cnn1d.csv      9 行   P1/P2 × raw_signal × cnn1d × 种子 0

**1 行 = 一次完整的训练+测试**（一个协议的一折，用一个特征集，训练一个模型，
用一个随机种子）。续跑机制：train_eval 会跳过已存在的
(protocol, feature_set, model, seed, fold) 组合。

31 列逐列说明：

  【标识列】
  protocol         协议名 P1~P5
  feature_set      特征集名 F1~F8 或 raw_signal
  model            模型名 lr/svm/rf/hgb/mlp/vote/cnn1d
  seed             随机种子（0/1/2；影响 RF 的抽样与 MLP 的初始化）
  fold             折名（与 splits_all.json 第二层键一致）

  【规模列】
  n_train_files    训练集文件数
  n_test_files     测试集文件数
  n_train_windows  训练集窗数
  n_test_windows   测试集窗数
  n_features       实际输入模型的特征维数
                   （cnn1d 为 1536，即重采样到 12 kHz 后的 0.128 s 点数）

  【耗时列】
  fit_seconds          训练耗时（秒）
  predict_ms_per_1k    每 1000 个窗的预测耗时（毫秒）—— 题目关注"实时性"，
                       这个数越小越适合在线部署。本次范围 0.19~5150 ms，
                       MLP 因为逐批推理最慢，线性模型最快。

  【窗口级指标】
  accuracy      总体准确率
  macro_f1      四类等权 F1 ← **主指标**
  weighted_f1   按样本数加权的 F1
  n_classes     该折实际出现的类别数（4 或 3；P1 fold4 为 3）

  【文件级指标】（同一次实验、把同文件的窗多数投票后再评估）
  file_accuracy       文件级准确率
  file_macro_f1       文件级 macro-F1
  n_test_files_eval   参与文件级评估的文件数

  【逐类指标】（每类三个，类名后缀 B/IR/OR/N）
  precision_X   查准率     recall_X  查全率     f1_X  该类 F1
  当某类在该折测试集中不存在时（如 P1 fold4 的 N、P3/P4 的 N），
  该三列整行为空——**这是设计行为，不是缺失**。

  本次要点（窗口级 macro-F1 均值）：
    P1  最好 cnn1d 0.936（F1+hgb 0.903，F7+rf 0.872，F2+hgb 0.768，F3 0.691）
    P2  最好 F1+hgb 0.957
    P3  最好 F3+vote 0.675
    P4  最好 F3+hgb 0.497（F7 仅 0.278）
    P5  最好 F7+rf 0.891
    f1_N 在 F2/F3 上普遍很低（0.18~0.48），是 macro-F1 被拉低的主因。

  读取方法（Python）：

2.12  group_ablation.csv —— 特征组剔除法消融（18 行 × 5 列）★关键★
--------------------------------------------------------------------------------
生成脚本：explain.py 的 group_ablation()。做法：先用 F1（全部 91 特征）
跑一个基准，然后**整组剔除**某一类特征再跑一遍，看性能变化。
模型固定 svm，协议取 P1/P3/P4。

  protocol     协议名 P1/P3/P4
  removed      被剔除的特征组名，取值：
                 "-"                   基准（不剔除）
                 time_dimensionless    无量纲时域（12 个）
                 time_raw_dim          未归一化的量纲时域（6 个）
                 freq_absolute         频域/包络谱（16 个）
                 order_generic         阶次-几何无关（37 个）
                 order_theoretical     阶次-理论阶次（20 个）
  n_features   剔除后剩下的特征数
  macro_f1     剔除后的 macro-F1
  delta        = 剔除后 − 基准。**正数表示"去掉反而更好"（该组有害），
               负数表示"去掉变差"（该组有用）。**

  本次读数（关键六行）：
        协议  剔除的组               delta        解读
        P1    order_generic          +0.065   同分布下阶次特征是**噪声**
        P1    freq_absolute          −0.052   频域特征有用
        P1    time_raw_dim           −0.025   量纲时域有用
        P4    order_generic          −0.097   跨设备下阶次特征**最关键**
        P4    order_theoretical      −0.094   理论阶次同样关键
        P4    time_dimensionless     +0.065   跨设备下无量纲时域反而有害

  ★ 结论：**同一组特征，在 P1 上有害、在 P4 上最关键**。
    这与 feature_set_compare.csv 的排序反转是同一现象的两种验证方式，
    也是任务三必须做域适应（而不是简单复用源域模型）的根本原因。
  注意：只做了 P1/P3/P4 三个协议、只用了 svm 一个模型，是为了控制耗时
        （全组合需 3 协议 × 6 组 × 多模型 × 多折）。

2.14  noise_robustness.csv —— 加噪鲁棒性汇总（5 行 × 7 列）

2.16 ~ 2.19  noisy_features_snr{20,10,5,0}.csv —— 加噪特征表
--------------------------------------------------------------------------------
生成方式：对原始振动信号加高斯白噪声（噪声功率 = 信号功率 / 10^(SNR/10)），
          再用**任务一的同一套代码**（features_time / features_freq /
          features_order）重新提取特征。每个文件约 7 MB，4120 行 × 96 列。

列结构 = 任务一 features_source.csv 的 91 个特征 + 5 个元数据列：
    file_id, group, fs, fault_type, load
    t_*       时域 12 个（t_mean_abs, t_rms, t_std, t_var, t_peak, t_p2p,
              t_kurtosis, t_skewness, t_crest, t_impulse, t_clearance, t_shape）
    f_*       频域与包络谱 16 个（f_centroid, f_msf, f_rmsf, f_variance,
              f_peak_freq, f_entropy, f_spec_kurt, f_env_log_energy,
              f_{BPFO,BPFI,BSF,FTF}_ratio1, f_{...}_harm_frac）
    o_*       阶次-几何无关 37 个（o_pk0~7 各 order/amp/ratio 共 24，
              o_entropy, o_kurtosis, o_crest, o_gini 共 4，
              o_bandfrac0~4 共 5，o_shaft1/2/3/21 共 4）
    o_theo_*  理论阶次 20 个（4 个特征频率 × (1~4 次谐波 ratio + frac)）
    t_*_rel   6 个按文件归一化的量纲时域特征
    （各列的确切含义、单位、公式见任务一的 outputs_result_anls.txt 第 0 与 2.9 节）

  与任务一 features_source.csv 的差别：
    ① 元数据列少 6 个（没有 domain / win_idx / win_start / rpm /
       fault_size / or_position），只保留识别与标签所需的最少列；
    ② 噪声经过同一提取流程，因此**可与干净特征直接比较**。
  用途：加噪鲁棒性实验的输入；也可用于任务三做数据增强的对照。

5. 常见疑问
================================================================================
Q1 为什么 runs_*.csv 里有些行没有 precision_N / f1_N？
   该折测试集中没有 N 类。P1 fold4、P3、P4 都会出现这种情况，
   n_classes 列会同时变成 3，看到这两个信号就说明该行是 3 类任务。

Q2 为什么 summary_by_model.csv 比 runs_*.csv 行数少这么多？
   runs_*.csv 每行是"一次实验"，summary 把它按 (协议, 特征集, 模型) 聚合，
   所以 114 = 各组合的个数（3 个种子与多折被平均掉了）。

Q3 protocol_shift.csv 里 P2 的 drop_vs_P1 是负数，是不是错了？
   不是。P2 是按载荷整档留出，测试集更"同质"（载荷只影响转速与幅值，
   而特征已归一化），所以分数反而比随机划分的 P1 高。这说明载荷不是
   主要域差异来源。

Q4 feature_set_compare.csv 里的 NaN 是什么意思？
   raw_signal 那一行的 P3/P4 为 NaN，表示 M5（WDCNN）只跑了 P1/P2，
   不是数据缺失或读取失败。

Q5 group_ablation.csv 里 delta 是正的，是好还是坏？
   正数表示"剔除该组特征后性能变好"，即该组在**该协议下**是噪声或干扰。
   P1 的 order_generic 是 +0.065（有害），P4 的 order_generic 是 −0.097
   （有用）——同一组特征在两种协议下结论相反，这正是关键发现。

Q6 noise_robustness.csv 显示 10 dB 比 clean 还好，模型是被噪声"增强"了吗？
   不是。这是 macro-F1 在 N 类上的不稳定造成的假象（N 每折仅 1 个文件），
   标准差 0.14 远大于真实差异。该表目前只应作为"指标不稳定"的证据。

Q7 noisy_features_snr*.csv 能删吗？
   能。它们是加噪实验的中间产物，共约 28 MB。删掉后重跑
   `python noise_robustness.py` 会重新生成（约 6 min）。

Q8 source_model_F2.pkl 能直接对 features_target.csv 用吗？
   能，但**必须**用 pickle 里自带的 pipeline 做变换，且列顺序要用
   columns 字段指定的顺序。直接拿原始特征列喂给 estimator 会得到错误结果。
