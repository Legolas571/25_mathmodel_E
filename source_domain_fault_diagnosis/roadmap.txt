3. 数据事实与三个必须处理的问题
================================================================================
3.1 问题一：极端类不平衡（N 类只占 2.7%）
    窗级：OR 1923 / B 1048 / IR 1037 / **N 112**
    文件级：OR 77 / B 40 / IR 40 / **N 4**
    → 若用 accuracy 作指标，把所有样本判成 OR 也能拿 46.7%，毫无意义。
    → 处理：
       (a) 主指标改用 **macro-F1**（各类等权），accuracy 只作参考；
       (b) 训练时用 class_weight="balanced" 或 Focal Loss；
       (c) 报告 N 类的 recall/precision，单独看这一类的表现；
       (d) **禁止用随机过采样到窗级**（会把同一文件的窗重复采样，等于泄漏），
           如需过采样只能在文件级做或在损失里加权。

3.2 问题二：N 类只在 48 kHz 出现
    文件级交叉表（类别 × 采样率）：
        B   12 kHz 28 / 48 kHz 12
        IR  12 kHz 28 / 48 kHz 12
        OR  12 kHz 49 / 48 kHz 28
        N   12 kHz  0 / 48 kHz  4
    分组交叉表（类别 × 分组）：
        12k_DE   B16 IR16 OR28 N0
        12k_FE   B12 IR12 OR21 N0
        48k_DE   B12 IR12 OR28 N0
        48k_Normal B0 IR0 OR0 N4
    → 后果 1：如果随机划分里 12 kHz 与 48 kHz 的窗混在一起，模型可能靠
       "采样率"识别 N 类，得到虚高精度（任务一的 figures/audit_class_dist.png
       已经把这个问题画出来了）。
    → 后果 2：任何"跨采样率"的划分协议里 **N 类都无法参与**（训练侧没有 N
       或测试侧没有 N），必须显式降为 3 类任务并说明。
    → 处理：
       (a) 增加一个"同采样率"的干净对照协议（只用 48 kHz 的 56 个文件，
           四类齐全），用于验证模型不是靠采样率作弊；
       (b) 跨采样率协议只做 3 类（B/IR/OR）；
       (c) 在报告中如实说明该限制，不要回避。

3.3 问题三：同一文件的窗高度相关 → 划分单位必须是文件
    每个文件切出 15~31 个 0.5 s 窗，相邻窗重叠 50%，共享同一轴承、同一转速、
    同一载荷、同一故障尺寸。
    → 必须用任务一的 splits.json（按文件划分），或在 make_splits.py 里按文件重建。
    → 严禁 `train_test_split(X)` 这种按行随机切分。

4. 划分协议设计（任务二的核心方法论）
================================================================================
设计 4 套协议，分别回答 4 个问题。全部**以文件为单位**划分。

  协议   名称                     划分方式                        回答的问题
  --------------------------------------------------------------------------
  P1     随机文件 5 折            按类别分层，把文件分 5 折        诊断能力的上限
                                  （直接复用任务一 splits.json）
  P2     留一载荷 (LOLO) 4 折     每次把某一载荷的全部文件作测试    跨工况泛化能力
                                  （载荷 0/1/2/3 各当一次测试）
  P3     跨采样率 2 折            12k 训练 → 48k 测试，反之亦然    跨采样率泛化
                                  **仅 3 类 B/IR/OR**（见 3.2）
  P4     跨传感器位置 2 折        12k_DE 训练 → 12k_FE 测试        跨传递路径泛化
                                  （同采样率，**仅 3 类**）        （为任务三的
                                                                  "跨设备"做准备）
  --------------------------------------------------------------------------
  可选 P5  仅 48 kHz 干净对照    只用 56 个 48 kHz 文件做 5 折    排除采样率混淆
           （四类齐全）

  为什么 P2/P3/P4 特别重要：
    目标域是**另一台设备、另一种转速、另一种采样率**。源域内部这三套协议
    正好分别模拟了"工况差异""采样率差异""传递路径差异"三种域偏移。
    它们的结果直接决定任务三该选哪一类特征、哪一种迁移方法：
      - 若 P3 中阶次域特征远好于绝对频率特征 → 阶次域方案成立；
      - 若 P4 掉得很厉害 → 说明"传感器位置/传递路径"是主要域差异，
        任务三需要重点对齐这一类；
      - 若 P2 掉得很厉害 → 工况差异是主要矛盾。

  输出：splits_all.json，结构
        {"P1": {"0": {"train": [...], "test": [...]}, ...},
         "P2": {...}, "P3": {...}, "P4": {...}, "P5": {...}}

6. 预处理规范（严格防泄漏）
================================================================================
  流程（全部只在训练折上 fit，测试折只 transform）：
    (1) 缺失值：实测为 0；仍保留兜底 —— 训练折中位数填充；
    (2) 异常值截断：按训练折的 1% 与 99% 分位数做 winsorize（可选开关）；
    (3) 标准化：StandardScaler 或 RobustScaler（默认 Robust，抗离群）；
        决策树类模型（RF/HistGB）不需要标准化，但统一走同一接口；
    (4) 类权重：class_weight="balanced"（sklearn）或 Focal Loss（torch）；
    (5) 可选降维：PCA（仅用于可视化与"降维是否有损"对照）；
    (6) **禁止**：用全量数据 fit 标准化器；用测试折信息做特征选择。

  记录：每个实验都保存所使用的标准化器参数（均值/尺度或中位数/IQR），
        与最优模型一起打包，供任务三复用（任务三必须用**同一套**变换）。

8. 实验矩阵
================================================================================
  维度：协议(P) × 特征集(F) × 模型(M) × 随机种子(S)

  完整跑：5 P × 8 F × 7 M × 5 S = 1400 次训练
    - sklearn 模型单次约 0.5~3 s → 可控
    - MLP 单次约 10~30 s（GPU）→ 约 8 分钟量级
    - 1D-CNN 单次约 1~2 min → 只做关键组合

  因此分三阶段执行，避免组合爆炸：
    阶段 1（主实验）：P1/P2/P3/P4 × F1/F2/F3/F6/F7 × M0~M3 × 5 种子
    阶段 2（深度）：P1/P2 × F2/F3 × M4/M6 × 5 种子
    阶段 3（可选）：P1 × F2 × M5（原始信号端到端）

  每次实验记录一行结果到 results/runs.csv，字段：
    protocol, feature_set, model, seed, n_train_files, n_test_files,
    n_train_windows, n_test_windows, accuracy, macro_f1, weighted_f1,
    f1_B, f1_IR, f1_OR, f1_N, recall_N, precision_N, fit_seconds, predict_ms_per_1k
  汇总表 results/summary_by_model.csv 给出 mean ± std。

11.3  data_io.py
--------------------------------------------------------------------------------
  作用：把任务一的 CSV 变成模型要的张量，并保管所有元数据。
  关键函数：
    load_source_features() -> DataFrame
        读取 features_source.csv；校验列是否与 dataset_card 一致；
        打印形状与类别分布自检信息。
    load_splits(protocol, path=None) -> dict
        读取 splits_all.json 的某个协议；不存在时提示先跑 make_splits.py。
    feature_columns(df, key) -> list
        按 config.FEATURE_SETS[key] 的规则返回列名；同时报告实际列数
        （与预期不符时抛错，防止任务一改了列名而这里静默出错）。
    build_xy(df, cols, classes=None) -> (X, y, meta)
        classes 不为 None 时只保留这些类（用于 P3/P4 的 3 类任务）。
    group_split(df, split) -> (train_df, test_df)
        **按 file_id** 取子集（不是按行号），并在返回前断言
        train 与 test 的 file_id 集合无交集（防泄漏的硬校验）。
  输出：无（返回内存对象）。

--------------------------------------------------------------------------------
11.4  make_splits.py
--------------------------------------------------------------------------------
  作用：生成 5 套划分协议，落盘 splits_all.json，并打印每折的类别构成。
  关键函数：
    p1_random(df, k=5, seed=42)
        按 fault_type 分层，把文件分 5 折（与任务一 splits.json 同构，
        可直接复用任务一的文件，保证两边一致）
    p2_leave_one_load(df)
        载荷 0/1/2/3 各当一次测试折 → 4 折
    p3_cross_sampling_rate(df)
        2 折：12k（105 文件，3 类）训练 / 48k_DE（3 类）测试，以及反向；
        **显式剔除 N 类**并在日志里说明原因
    p4_cross_position(df)
        2 折：12k_DE 训练 / 12k_FE 测试，以及反向；3 类
    p5_clean_48k(df, k=5, seed=42)
        只用 48 kHz 的 56 个文件（四类齐全）做 5 折，作为排除采样率混淆的对照
    write_splits(...)  统一落盘并打印每折的 (n_files, n_windows, 类别分布)
  输出：results/splits_all.json
  自检：每套协议都必须满足"训练文件集合 ∩ 测试文件集合 = ∅"，
        否则直接抛异常终止。

--------------------------------------------------------------------------------
11.5  feature_prep.py
--------------------------------------------------------------------------------
  作用：特征表级的预处理，严格只在训练折上拟合。
  关键类/函数：
    class FeaturePipeline:
        __init__(scaler="robust"|"standard", winsorize=None, pca=None)
        fit(X_train)      计算截断阈值、均值/尺度（或中位数/IQR）、PCA 载荷
        transform(X)      应用上述参数
        fit_transform(X_train, X_test) -> (Xtr, Xte)
        save(path) / load(path)   与模型一起打包，供任务三复用
    compute_class_weight(y) -> dict
        "balanced" 公式：n_samples / (n_classes × bincount)
    class_weights_for_torch(y) -> Tensor
  要点：
    - 所有统计量只来自训练折；
    - winsorize 用训练折分位数，避免测试折极值影响；
    - PCA 仅可选，默认关闭（阶次特征本身维度不高）。

--------------------------------------------------------------------------------
11.6  models.py
--------------------------------------------------------------------------------
  作用：统一的模型工厂与接口封装，让 train_eval 能用同一段代码跑所有模型。
  关键函数：
    make_model(name, n_classes, seed, class_weight=None) -> 估计器
        "lr"      LogisticRegression(max_iter=2000, class_weight=...)
        "svm"     SVC(kernel="rbf", C=..., gamma="scale", probability=True,
                      class_weight=...)
        "rf"      RandomForestClassifier(n_estimators=500, class_weight=...,
                                         n_jobs=1, random_state=seed)
        "hgb"     HistGradientBoostingClassifier(max_iter=400, random_state=seed)
        "vote"    软投票集成（由调用方传入子模型列表）
    supports_scaling(name) -> bool   决策树类返回 False（可跳过标准化）
    fit_predict(model, Xtr, ytr, Xte) -> (y_pred, y_proba, fit_seconds)
  说明：所有模型统一 n_jobs=1，避免 Windows 沙箱下 joblib 探测 CPU 核失败。

--------------------------------------------------------------------------------
11.7  train_eval.py   ★主实验★
--------------------------------------------------------------------------------
  作用：执行实验矩阵，落盘每次运行的结果。
  命令行参数：
    --protocols P1,P2,P3,P4      默认全部
    --feature-sets F1,F2,F3      默认 config 中的主实验集合
    --models lr,svm,rf,hgb       默认全部 sklearn 模型
    --seeds 0,1,2,3,4
    --stage 1|2|3                阶段开关（对应第 8 节的三阶段）
    --tag 字符串                 结果表后缀，便于多次实验并存
  流程（对每个协议 × 特征集 × 模型 × 种子）：
    1) 取该折的训练/测试文件 → 按 file_id 取窗
    2) FeaturePipeline.fit(训练折) → transform 两侧
    3) make_model(...) → 训练 → 预测
    4) 计算指标 → 追加一行到 results/runs_<tag>.csv（**边跑边写，可中断续跑**）
    5) 若该组合是当前最优，序列化模型 + pipeline 到 models/best_<协议>.pkl
  输出：results/runs_<tag>.csv（每行一次实验）
        results/summary_by_model_<tag>.csv（按 协议×特征集×模型 聚合 mean±std）
  指标函数：accuracy / macro-F1 / weighted-F1 / 各类 P-R-F1 / 混淆矩阵 /
        推理耗时。N 类不存在时（P3/P4）相应字段留空并在表里标注 3 类任务。

11.8  report.py

    figures/cm_<协议>_<最优模型>.png  混淆矩阵（含每类 P/R/F1）

--------------------------------------------------------------------------------
11.10 model_torch.py（P1）
--------------------------------------------------------------------------------
  作用：PyTorch MLP + Focal Loss，专门对付 N 类样本太少。
  关键内容：
    class MLP(nn.Module)：输入 d → 256 → 128 → n_classes，
        每层 Linear + BatchNorm1d + ReLU + Dropout(0.3)
    class FocalLoss(nn.Module)：
        FL = −α_t (1 − p_t)^γ log(p_t)，γ=2，α 按类频倒数归一化
    训练：Adam(lr=1e-3)、batch 128、最多 200 epoch、
        早停（验证 macro-F1 连续 20 轮不升）、余弦退火
    设备：自动选 cuda（本机 RTX 3050 可用），否则 cpu
  输出：与 sklearn 模型同格式的结果行，写进同一张 runs.csv。

11.11 explain.py（P1）

  关键函数：
    permutation_importance_report(model, X_test, y_test, cols, n_repeats=10)
        逐特征打乱后看 macro-F1 下降幅度 → results/permutation_importance.csv
    group_ablation(...)
        按特征组（时域/频域/阶次几何无关/阶次理论）整组剔除后的性能变化
    misclassified_files(...)
        列出被错分的文件及其工况，输出 results/error_files.csv
  输出：上述 CSV + figures/permutation_importance.png

11.12 model_cnn1d.py（P2，可选）
--------------------------------------------------------------------------------
  前置：需要任务一先执行 `python build_dataset.py --save-windows` 生成
        windows_source_signal.npz（约 100~300 MB）。
  内容：WDCNN（第一层宽核 64、后续 3×3 卷积）+ 全连接分类头，
        输入 0.128 s 原始信号（12 kHz 为 1536 点，48 kHz 为 6144 点）。
  用途：作为"端到端深度模型 vs 手工特征"的对照；
        若手工特征已接近该模型，说明任务一的特征工程是有效的。
  注意：该分支要自己处理采样率不一致（分采样率建两个输入头或用插值统一）。

11.13 noise_robustness.py（P2，可选）
--------------------------------------------------------------------------------
  作用：模拟题目所说"源域存在轻微噪声影响"，检验模型抗噪性。
  做法：对原始信号加不同 SNR 的高斯白噪声（如 20/10/5/0 dB），
        **用任务一的特征提取函数重算特征**（直接 import 任务一的
        features_time/features_freq/features_order），再用已训练模型评估。
  输出：results/noise_robustness.csv + figures/noise_curve.png
       （x = SNR，y = macro-F1，多条曲线 = 不同特征集）
  说明：这是唯一需要跨目录调用任务一代码的模块，会用绝对路径
        sys.path 注入任务一目录（因为两个 config 同名，需显式处理）。
